一、这是什么，现在什么状态

目标：把歌声换成指定音色。两个模型分工：BS-RoFormer 先从整首歌里剥出干净人声干声，RVC 2.3 再把干声换成目标音色，最后混音。核心用法是把女声唱的歌转成用户自己的声音唱出来。

二、两个模型是干什么的

模型作用协议
RVC 2.3歌声转换：只换音色，不换唱功。音准、节奏、情感、转音咬字全来自源音频。MIT（可商用），2026-07 上游重建，支持 Python 3.12
BS-RoFormer人声分离：从整首歌里剥出干净人声干声。RVC 的最佳拍档，干声质量直接决定转换效果。权重以发布页声明为准，商用前核对

诚实边界：RVC 学不会唱腔风格、个人咬字、转音特点。要连风格一起克隆得走歌声合成（SVS，如 DiffSinger），需要大量带音高标注的数据，2026 年开源圈没有现成易用的方案。

补充（2026-10-26）：BS-RoFormer 的“最强”说法需加限定。阿力实测分离效果不好。论文榜单上 Mel-Band RoFormer 的人声 SDR 高于 BS-RoFormer，但不同 checkpoint、不同歌曲差异很大（MSST 榜单上 BS-RoFormer 人声 SDR 12.33 反而高于 Mel-Band RoFormer 的 11.30），榜单成绩不等于在你这首歌上的效果。不要凭单模型、单 checkpoint、单首歌下结论，替代方案见第十一节。

四、部署路线 A：Kaggle 免费 T4（推理 API）

Notebook 搭建顺序

  1. 环境：克隆 RVC 仓库，装 faiss-cpu、praat-parselmouth、einops、ffmpeg-python、av 等依赖；不要降级 torch（实测 torch 2.11.0+cu128 可用）。
  2. 下载底模：assets/hubert_base/pytorch_model.bin（181MB）、assets/rmvpe/rmvpe.pt（173MB），来源 HuggingFace lj1995/VoiceConversionWebUI。
  3. torch.load 幂等补丁（必须，torch ≥ 2.6）：补丁执行两次会无限递归，执行前必须检查 _rvc_patched 标志。
  4. convert 函数 + Gradio API：用仓库 infer/modules/vc/modules.py 的 VC 类封装推理，f0 用 rmvpe；接口签名 convert(audio_b64, model_name, f0_up_key=0, index_rate=0.75)；输入输出都用 gr.Textbox 传 base64 data URL，不要用 gr.Audio 等文件组件；demo.launch(share=True)，记录 *.gradio.live 公网地址。
  5. 验证：下载公开测试模型到 assets/weights/、assets/indices/，调 convert 确认返回有效 wav（字节数、采样率、时长）。

BS-RoFormer 同 notebook 加装

pip install audio-separator onnxruntime-gpu；separate(audio_b64) 解码为临时文件 → Separator.load_model("model_bs_roformer_ep_317_sdr_12.9755.ckpt")（懒加载）→ 按文件名含 vocal / instrumental 挑两轨 → 返回人声与伴奏的 base64。Gradio 同 app 挂第二个接口 api_name="separate"，重跑 launch(share=True)（地址会变）。

API 调用格式

POST https://<xxx>.gradio.live/gradio_api/call/convert
Body: {"data": [audio_b64_data_url, "model.pth", 0, 0.75]}

GET https://<xxx>.gradio.live/gradio_api/call/convert/<event_id>  (SSE)
# SSE: event: complete + data: [result_b64, info文本]（Gradio 6.26 实测）

实测耗时（2026-10-14，网络正常）

pip 装包约 50 秒；底模下载约 15 秒；Gradio 启动约 25 秒；推理 8 秒音频约 0.5 秒（Features 0.13s / F0 0.08s / Synthesis 0.29s）。女声转男声：f0_up_key=-12（降一个八度）。

Kaggle 会话生存规律（实测结论）

  • 免费 T4 无固定存活时长，Kaggle 可随时回收；高峰期（北京时间晚间 = 美东白天）几分钟就被杀，空闲时（北京时间上午 = 美东深夜）可跑较久。长任务排北京时间上午。
  • 回收会清空 /kaggle/working（pip 包、下载的模型、运行的服务全没），但 notebook 代码格子保留；每次新会话都要重跑部署（约 3–5 分钟）。
  • 把模型做成 Kaggle Dataset 挂载，省每次重下几百 MB；训练 checkpoint 每 25–50 epoch 存一次，存成 Dataset 防丢。
  • 配额 30 小时/周；同时只允许 1 个交互式 GPU 会话——RVC 和分离必须同 notebook。
  • 浏览器窗口闲置约 2 小时自动关；Kaggle 额度只算会话开着的时间，空挂也烧。

六、训练流程（训自己音色）

数据准备

  • 格式：WAV 单声道 44.1kHz 最好，MP3 也能用但 WAV 更稳。
  • 内容：清唱 10–20 分钟 + 说话 10–20 分钟最优；只给清唱也行，20–30 分钟为佳，1 小时封顶（超过 1 小时几乎听不出差别、只浪费训练时间）。
  • 要求：安静干声环境（衣柜等），无混响；全程同一设备同一音量；覆盖高 / 中 / 低音、长音颤音、快慢风格；不要过度降噪。
  • 原则：干净、多样 > 堆时长。RVC 吃进去什么，吐出来就是什么质感。

训练步骤

  1. 预处理：音频切段 → 重采样 → RMVPE 提 F0 → Hubert 提特征。T4 上约十几分钟。
  2. 训练：200 epoch。T4 参考 2–3 小时（社区 claim，误差 ±50%）；50 分钟数据约 3–4 小时；batch_size 默认 8，显存不足调小。
  3. Checkpoint：每 25–50 epoch 存一次。Kaggle 上存成 Dataset（防会话回收丢进度）。
  4. 产物：.pth（模型）+ .index（检索索引），放到推理服务的 assets/weights/ / assets/indices/，前端页填模型名即可用。

训练产物就是两个独立文件，可从 Kaggle 下载到本地直接用，或存成 Kaggle Dataset 下次部署挂载免重训。

七、排障：已知坑与修法

1. torch.load 无限递归（RecursionError）

症状：补丁重复执行，递归数千次后 RecursionError。修复：补丁幂等化——执行前检查 getattr(torch.load, "_rvc_patched", False)，用闭包包装且只包一层。注意：torch 2.11 下 rogue.pth 仍可能 RecursionError（版本与该 checkpoint 不兼容），备选是把 torch 降到 2.7.1（该版本曾加载成功）。

2. Gradio 6.x 文件组件经 API 变空

症状：cannot reshape tensor of 0 elements，服务端收到空张量。原因：gr.Audio / gr.Image / gr.File 经 /gradio_api/call 传入有 bug（gradio_client 2.7.2 同样）。修复：输入输出改 gr.Textbox 传 base64 data URL，函数内直接解码，不经过文件系统。

3. onnxruntime-gpu 版本与 CUDA 兼容

1.31.0 曾报 libcublasLt 相关错误；降到 onnxruntime-gpu==1.22.0（CUDA 12 兼容）后验证有效，BS-RoFormer 分离可跑到 60%（3/5 segments）不再报错。

4. 底模必须实际落盘到 assets/

10-15 重部署时 hubert_base 下载 cell 未实际落盘（HF 缓存为空），导致 load_hubert 报 IndexError。修法：底模落盘到 assets/ 并逐项校验，最好做成 Kaggle Dataset 挂载，省每次重下几百 MB。

5. separate 输出文件名匹配要健壮

10-15 的 separate 曾因输出文件查找逻辑 bug（sep.separate() 未返回预期含 vocal / instrumental 命名的两个文件，后备逻辑越界）报 IndexError。修法：文件名匹配改健壮，不要假设固定命名。

6. Kaggle 会话被回收

现象：Gradio 地址 404，notebook 显示会话停止。处理：重建会话，按 cell 顺序重跑（约 3–5 分钟）。预防：长任务排北京时间上午，checkpoint 勤存。

7. Hubert 特征提取静默失败（10-17 最后机会失败根因）

现象：Cell 报告成功但实际 0 产出（logs/rvc_caiqin/3_feature768/ 为空），随后因缺 filelist.txt 导致训练退出，0 个 epoch。5090 修复版已针对性加固：Hubert 底模补齐三件套并逐项校验、去掉所有日志截断、每步加输出断言、训练启动前确认特征目录非空。

十一、BS-RoFormer 替代方案（2026-10-26 补充）

按验证成本从低到高排：

  1. Mel-Band RoFormer（同门换 checkpoint，成本最低）。把 BS-RoFormer 的频带切分换成 mel 尺度重叠频带，论文人声 SDR 高于 BS-RoFormer，声音更平滑、响度更一致。UVR 里有现成模型，同一首歌直接对比听。
  2. Demucs htdemucs_ft（开源标杆）。Meta 的混合 Transformer Demucs，微调版质量再进一步，pip install demucs 就能跑，5090 上飞快，适合做对照组。
  3. UVR5（免费桌面应用，不想折腾代码的首选）。把 Demucs、MDX-Net、RoFormer、MDX23C 全包了，还能调后处理、降噪、去混响；Windows 电脑就能跑，CPU 也行就是慢。
  4. 多模型 ensemble（效果天花板）。MVSEP 的做法：BS RoFormer + Mel-Band RoFormer + SCNet XL 三模型结果平均，2025.06 版 ensemble 人声 SDR 11.93，是目前公开榜单最高的打法。代价是 3 倍算力 + 拼接工作量，适合某一首特别重要的歌。
  5. 在线付费参照（验证用）。LALAL.AI、Moises、StemSplit（后者用 Demucs 同款，按分钟约 $0.10/分钟）——拿一首歌做参照，验证到底是模型问题还是这首歌本身难分。

验证方法：同一首歌的副歌段，2–3 首不同风格对照；验收标准按 RVC 的需求来——不是伴奏好不好听，而是人声干声里漏了多少伴奏、有没有“水声”/金属 artifacts、高音和气声保没保住。
