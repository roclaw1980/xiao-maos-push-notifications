Qwen-Image 2.1 实测复核与建议

2026-10-21 · 小毛大管家（搜索 + 上机实测）
复核对象：《Qwen-Image 2.1 自建算力出图 —— 测速与归因报告》（下称「原报告」）
环境：同一台 AutoDL A100-40GB 实例、同一商品（OnlyFires 贴纸）、同一组 5 张参考图、用户原提示语，ComfyUI 0.42.0 / torch 2.14.1 / bf16 Turbo 权重
一句话结论：原报告测出的 57 秒里，藏着一个模板参数问题。
实例上官方 Turbo 编辑模板自带的 CFGGuider 是 cfg = 8，但 ComfyUI 官方文档写明 Turbo 的发布路径是 cfg = 1（cfg 1 时负向条件整段跳过）。我逐项实测：只改这一个数，生产单张从 57.2 秒 → 36.9 秒；用户最初抱怨的绿色斑点和背景渐变同时消失（像素级统计：背景标准差 18.7 → 0.6，绿色异常像素 261 → 0）。原报告悬而未决的「25 秒首步」也定位完毕：就是 KV 前缀缓存的构建，被 cfg 8 构建了两遍。

二、三个病根的最终判定

1. 「25 秒首步」＝ KV 前缀缓存构建（原报告 §10 待办 1，已定位）

官方文档对 QwenImage21Cache 节点的说明：它把「文本 + 参考图前缀」的 KV 缓存保存在采样步之间复用。实测证据链：

  • 进度条把这段时间单独标为 Model Initializing，发生在第 1 步之前；
  • cfg 8 → 27s，cfg 1 → 12s：正好约 2 倍，因为 cfg>1 时正、负两个条件分支各建一份前缀缓存；
  • 把缓存节点设为 device=off：Initializing 降到 1s，但每步采样从 0.75s 涨到 ~3.1s（每步重算前缀），且输出与开缓存时像素级完全一致（平均差 0.0）——缓存只影响速度、不影响结果，机理坐实；
  • 与参考图张数非线性：3 张时构建只要 ~1s，5 张跳到 12s（原报告的线性拟合是在 cfg 8 下做的，掩盖了这一点）。疑似与缓存体积跨过某个显存/分块阈值有关，未再深挖——不影响结论。

⇒ 不是原报告候选的 aimdo host_buffer 问题，也不是显卡问题；这是该编辑架构的固有成本，只能靠降 cfg、减参考图削减，换卡只能等比例压缩。

2. 绿斑 + 背景渐变 ＝ cfg 8 的过度引导伪影（原报告 §8，已定案）

同一商品、同一提示语、种子可比条件下做背景像素统计（取画面四边条带）：

cfg 8（E1）cfg 1（E2/E6/E8）
背景 RGB 标准差18.7 / 12.8 / 4.00.6 / 0.6 / 0.6
左上角 vs 右下角底色(76,34,0) vs (122,66,8)，明显晕影(111,71,39) vs (110,72,39)，一致
绿色异常像素数2610

机理与官方文档互证：文档明确写高 cfg 会「偏移曝光、cfg 5 画质严重下降」，而 Turbo 的发布路径就是 cfg 1。原报告此前把绿斑怀疑到量化精度和 VAE 上——bf16 只减轻了一点，正是因为病根不在那里。结论：绿斑不需要换 VAE、不需要换 Base 模型，改 cfg 即可。

Texture-Fix VAE（madebyollin，官方文档亦推荐）我下载并实测了：背景高频微纹理噪声 0.49 → 0.30（约降 40%），底色与纯净度与原 VAE 无异。它治的是照片类细节图的棋盘格微纹理，对贴纸这种平涂图是小改进——零成本（同体积、同速度），建议顺手换上，但别指望它治绿斑。文件已放在实例 models/vae/texture_fix_vae_for_qwen_image_2.1_bf16.safetensors。

3. 主图案阴影 ＝ 模型先验，生成侧无解，走后处理

阴影在全部配置下纹丝不动：int8/bf16、cfg 8/1、两种 VAE、3/5 张参考图——我这轮再次全量确认。它是语义层面的东西：所有参考照片里贴纸都贴在车身上，模型默认「贴纸下面该有影子」。提示语已写明无阴影，cfg 1 下又没有负向提示可用，继续在生成参数上死磕收益为零。

生产解法：放到后处理。cfg 1 的背景已是标准差 0.5 的近完美纯色，抠图门槛极低：按底色距离分割（或 BiRefNet 一类抠图模型）提取贴纸 → 合成到目标纯色（或直接导出透明底 PNG），阴影和底色偏差一并清零，底色还能保证与上架规格分毫不差。这一步顺便把「背景必须精确为某个色值」也变成确定性操作，不再靠生成运气。

四、建议清单（按优先级）

1. 批量管线里把 cfg 写死为 1，其余参数照官方模板（8 步、ManualSigmas 原样、euler）。这是本轮唯一需要改的参数，速度和质量同时受益。附带一条：文字特别密集的商品，建议抽 2–3 个样本对比 cfg 1 与 cfg 2（官方文档说 cfg 2 对小字、数字的跟随更好，但会略微过锐）——本商品的文字在 cfg 1 下完全正确，所以只作抽测，不作默认。
2. 参考图保持 5 张出定稿；3 张只作快速预筛。原报告「减到 2 张文字崩」的现象大概率也混着 cfg 8 的伪影，但 3 张的构图退化是我亲眼所见，别为省时间赌定稿质量。
3. VAE 换 Texture-Fix 版（已下载到实例，可直接选用）：微纹理噪声降约 40%，零代价。照片类商品图收益会比贴纸更明显。
4. 阴影与底色交给后处理：生成（cfg 1）→ 抠图 → 合成标准底色/透明底 → 质检。不要在提示语和参数上继续纠缠阴影。
5. 机器去留：A100 先留着，另花约 3 元做一次 5090 对照。本轮证明瓶颈主要是软件参数而非显卡；但官方文档给的 5090 编辑速度约 0.3 s/it（1MP），对比这台 A100 在 cfg 1 下约 0.75 s/it，Blackwell 对编码与前缀构建也应有等比例收益——租 1 小时 5090（包月口径约 ¥2.44/h、按需约 ¥2.4–3.6/h）用同一套 cfg 1 参数跑同商品对照，即可定全量跑批用哪张卡。预期 5090 单张可到 15–20 秒级，总成本再降一截，但以实测为准。注意：实例磁盘只剩 12G，若要下 Base 模型（约 14G），先删 int8 Turbo 权重（7.2G）腾地方。
6. 可以结案的悬案：原报告 §10 的待办 1（25 秒机理）已定位（本报告第二节 1）；待办 3（resolution 512→768 陡崖）未复测，生产用 1024 不受影响，优先级最低；Base 模型（待办 2）在 cfg 1 结论出来后已无必要为「治绿斑」而下，仅当想要更高画质上限时再考虑。
