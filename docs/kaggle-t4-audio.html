ACE-Step ACE Studio + StepFun

Diffusion 架构（v1.5 为 LM planner + DiT renderer + DCAE）。歌词/标签/描述 → 完整歌曲，另支持翻唱、音轨分离、局部重绘、LoRA。社区质量评价约 Suno v4.5–v5（社区主张）。

模型卡坦承的局限：人声合成较粗糙、中文说唱等风格偏弱、对随机种子敏感。注意版本选择：v1.5 的 4B XL turbo 在 T4 上需 CPU offload + INT8（≥12GB），不推荐；v1 3.5B 是稳妥选择。官方提供 Gradio UI，可直接改造为 API。

DiffRhythm ASLP-lab · 西工大

首个 latent diffusion 端到端歌曲生成模型：歌词+风格 prompt → 最长 4 分 45 秒完整歌曲，人声+伴奏一次生成；非自回归，所以极快。官方 README 明确最低 8GB 显存（用 --chunked）。

升级版 DiffRhythm+（偏好优化）与 DiffRhythm 2（2025-10 论文）在 4090 上生成 2 分钟分别需 18.3 秒 / 25.6 秒。社区质量评价约 Suno v4（社区主张）。官方提醒：生成音乐商用需自行做原创性核查。

SongGeneration v2-large 腾讯 AI Lab · LeVo 2

混合 LLM+Diffusion，一次生成人声+乐器，最长 4 分 30 秒，多语言含中文。标准模式需约 30GB 显存，低内存模式（USE_LOW_MEM=true）约 10GB 可上 T4。

短板是速度：4090 上 2 分钟需 147 秒（RTF 1.225，慢于实时），T4 上 3 分钟歌曲估计 7–10 分钟。适合不赶时间的离线任务——愿意牺牲速度换质量时可试。

PART 3

用自己的声音唱歌：歌声克隆

追问的目标：录一段自己的声音做素材，让「自己」去唱任意一首歌。结论——完全可行，两条路线：零训练路线当天出歌（Seed-VC，1–30 秒参考音频即可换声）；训练路线音质最好（RVC，10–30 分钟录音训一个专属音色模型，T4 上约 2–3 小时训完）。注意 ACE-Step 本体没有参考人声克隆功能（官方 issue 已明确），必须在生成歌曲之后外挂一步换声。

1 · 生成歌曲ACE-Step 1.5 / DiffRhythm 出完整歌曲（人声+伴奏）
→
2 · 分离干声UVR5 / Demucs / BS-RoFormer 把人声从伴奏里剥出来
→
3 · 换成你的声音Seed-VC 零样本换声，或 RVC 已训好的个人模型转换
→
4 · 混音转换后的干声 + 原伴奏，用 ffmpeg 或任意 DAW 合并

路线 B · 训练，音质最好

RVC 2.3

RVC-Project/Retrieval-based-Voice-Conversion-WebUI

录音指南：照着录就行

录什么（最优组合）：清唱 10–20 分钟（覆盖舒适音区的高、中、低音，带长音、颤音、真假声转换）+ 朗读/说话 10–20 分钟。音域覆盖比「唱得好听」重要，多样性比重复重要，不要同一旋律反复录，录音里不要混入伴奏。

环境与格式：越干越好——衣柜/被子里是最便宜的「录音棚」（衣物吸声），关空调风扇、别加混响。WAV 单声道 44.1kHz。有入门电容麦（如 AT2020 级）+ 声卡更好；没有的话手机在安静衣柜里录也能用，但噪声与频响会限制上限。全程同一设备、同一距离、同一音量。

后期：可用 UVR 的去混响模型（VR-DeEchoAggressive 等）清理，但不要过度降噪，会损伤音色细节。

来源：RVC 官方 README 与 FAQ；Everyone-Can-Sing 论文（arXiv 2501.13870）；Qosmo SVC 综述（2026-10-14 读取）

其他方案：为什么不选它们

SoVITS-SVC 4.0 / 5.0：老牌唱歌换声，需训练、流程繁琐（多步预处理），4.0 为 AGPL-3.0 强 copyleft 且部分预训练权重是 CC BY-NC-SA 非商用，官方已归档；易用性已被 RVC 生态超越。

OpenVoice v2（MIT）：10 秒参考零训练克隆音色，但它只能「说话」不能唱歌——克隆的是音色、把文本读出来，不保留也不控制旋律音高，别拿它做翻唱。

DDSP-SVC（MIT）：更轻量的唱歌换声，工具链较少，适合资源受限场景。另有新兴一体化 GUI NVC（训练+推理+人声分离，数据标准沿用 RVC 的 ≥10 分钟），2026 年新项目，尚无大规模社区评测。

来源：SoVITS-SVC fork README；OpenVoice 镜像仓库；coding-misk VOCALS.md；kanoyo-git/nvc（2026-10-14 读取）

  • Kaggle 配额完全够用按社区速度推算：20 分钟数据集训 200 epoch 约 1.7 小时，含预处理与索引训练总计约 2–3 小时——在单个 6 小时会话内可完成，只占每周 30 小时配额的约 10%。Seed-VC 路线则完全没有训练压力。单会话上限 6 小时来自社区教程文档，Kaggle 官方限额可能调整，动手前以官方文档为准。
  • Checkpoint 策略（关键）会话结束 /kaggle/working 会被清空：训练时设每 25–50 epoch 保存一次，会话结束前把 logs/ 下最新 .pth 与 .index 存为 Kaggle Dataset 或下载到本地；新会话挂载后可用 -pg/-pd 参数从已有权重续训。更省事的做法是 Save & Run All 后台运行（最长 12 小时，可关浏览器），一次跑完 200–300 epoch。用 GPU 前需先验证手机号。
  • 为什么不用 Colab2026 年 Colab 免费层对 WebUI 类 notebook 限制严格（需付费 compute units / Pro），RVC 的 Kaggle/Colab 笔记本仓库明确建议改用 Kaggle 每周 30 小时免费 GPU 跑 RVC_CLI.ipynb。
  • 预期效果说话+唱歌混合数据训出的模型：音色相似度与演唱自然度都明显更好；纯说话数据也能用，旋律跟随准确，但高音、长音、颤音的质感会打折。翻唱他人歌曲另请注意原曲版权。
部署

落到 Kaggle 上的注意事项

模型选完只是第一步。Kaggle 免费档的配额、回收与冷启动，才是这台「引擎」实际可用性的决定因素。

  • 配额与抢占免费档每周 30 小时 GPU；高峰时段 session 可能被回收。歌曲生成单次耗时分钟级，要控制单次任务长度，产物及时保存到 /kaggle/working 并尽快下载到本地。
  • 冷启动成本/kaggle/working 在回收后清空，每次启动需重下模型。TTS 模型 0.3–2GB（约 1–3 分钟下完）；ACE-Step 约 9–10GB（预计 5–15 分钟，Kaggle 外网通常较快）。建议首次启动只做「下载 + 冒烟测试」，通过后再暴露 Gradio API。
  • 单卡驻留策略TTS（CosyVoice 3 约 4GB）与歌曲模型（ACE-Step 约 8–10GB）不要同时驻留显存：Gradio 服务内按需加载、用完 torch.cuda.empty_cache() 释放，或拆成两个 Kaggle notebook 分别 serving。
  • 接口形态TTS 均为快于实时，可同步调用；歌曲类 3 分钟成曲预计 1–10 分钟，API 应做成异步任务 + 轮询，不要同步等待。
  • 依赖细节CosyVoice 3 需要 ttsfrd 中文前端；ACE-Step 官方提供 Gradio UI（python acestep --config-path ...），可直接改造为 API；DiffRhythm 需 --chunked 才能满足 8GB。
  • 合规红线声音克隆务必获得被克隆人授权；ACE-Step / DiffRhythm 生成音乐的商用需自行做原创性核查（DiffRhythm 官方 README 有此要求）；Fish / Spark / F5 / ChatTTS / IndexTTS-2.5 / MelodyFlow / MusicGen 的权重不可商用。

还没确认的事

以下问题在本次调研中没有得到可靠答案，部署决策时按「未确认」处理，不要当成结论用。

  1. YuE2-3B 许可证：来源冲突（aiadoptionagency 称 CC 非商业；Pinokio launcher 徽标称 Apache-2.0）。核实前视为不可商用。
  2. IndexTTS-2 权重许可证：tts-bench 称 Apache-2.0，但 tts.ai 对比表与 voice-cloning-guide 称 Bilibili Model License（2.5 确认非商业）。商用前以 HF 模型卡当前 LICENSE 文件为准。
  3. T4 真机速度：所有 T4 耗时均为折算估算，未经真机验证；DiffRhythm 的「10 秒」是官方在强 GPU 上的说法。
  4. DiffRhythm 确切下载体积：未在官方渠道确认（约 1B 级，估计数 GB）。
  5. SongGeneration v2-large 确切下载体积：未确认。
  6. HeartMuLa 中文歌词实际质量：仅有多语言支持的社区主张，缺少中文专项评测。
  7. ACE-Step 1.5 在 T4 上的具体配置：4B XL turbo 需 CPU offload + INT8（≥12GB），v1 3.5B 更稳妥；1.5 的 2B turbo 变体未深入调研。
  8. E2-TTS：Seed-TTS 团队研究模型，无官方可直接部署的开放权重，未纳入推荐。
  9. RVC 在 T4 上的每 epoch 耗时（15 分钟数据集约 20–30 秒/epoch）：来自 RVC 官方 issue #1593 的一条社区回复，未经真机实测，batch_size、采样率、fp16 都会显著影响，误差可能 ±50%；「200 epoch 约 2–3 小时」同为推算。
  10. Seed-VC 微调耗时：官方 README 称 100 steps 在 T4 上约 2 分钟，为官方声明，未独立验证。
  11. RVCv3：官方 README 多次预告（更大参数、更少训练数据），截至 2026-10-14 未发布，无可用版本。
  12. NVC 的实际效果：2026 年新项目，仅从 README 了解功能，未见大规模社区评测。
  13. Kaggle 单会话 6 小时上限：来自社区教程文档，未直读 Kaggle 官方限额页面，动手前请以官方文档为准。
